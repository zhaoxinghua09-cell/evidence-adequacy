# Cross-tool comparison (results as of 2026-11-26)

Generated by `tools/erm_scorecard.py` (UIBC Core) and `adapters/proofbundle_adapter.py` (proofbundle), both on Windows 11 / Python 3.13.18.

| Verifier | version | mutants eligible | `open` kill rate | `pinned` kill rate | `head-pinned` | false reject |
|---|---|---|---|---|---|---|
| UIBC Core | 0.5.5 | 21 | **90.5%** (19/21), 95% CI [71.1, 97.4], B | **95.2%** (20/21), [77.3, 99.2], A | **100%** (21/21), [84.5, 100], A | 0/2 |
| proofbundle | 6.6.1 | 10 | **70.0%** (7/10), [39.7, 89.2], C | **80.0%** (8/10), [49.0, 94.3], B | N/A (no checkpoint fixture) | 0/2 |

## Escapes, named

| Tier | UIBC Core | proofbundle |
|---|---|---|
| `open` | `M17 key swap`, `M20 whole-bundle rollback` | `M03 key swap`, `M10 replay`, `M11 base64 alias` |
| `pinned` | `M20 whole-bundle rollback` | `M03 key swap`, `M11 base64 alias` |
| `head-pinned` | none | not measured |

## What the numbers mean

1. **Key substitution escapes at `open` for both** — correct behaviour: with no anchor, a self-signed bundle is valid against its own key. Any tool claiming to catch key substitution without pinning is wrong.
2. **proofbundle's `pinned` tier pins the content root, not the signer key.** Re-sign the same payload with an attacker key and the Merkle root is unchanged, so `--expected-root` still matches. This is not a bug report — it is a demonstration that **root pinning ≠ identity pinning**. UIBC Core's `M17` is caught at `pinned` precisely because its pin is a public key, and escapes only at `open`/unpinned.
3. **`head-pinned` is where rollback dies.** UIBC Core's only remaining escape (`M20 whole-bundle rollback`) disappears at `head-pinned` (21/21). proofbundle exposes `--trusted-checkpoint` for this tier but a checkpoint fixture was not constructed here, so the tier is `N/A` — **not** "unsupported".
4. **Base64 aliasing is a real family.** proofbundle accepts an unpadded Base64 payload that decodes to identical bytes; the verifier is tolerant where a stricter one might be. UIBC Core's own corpus does not include this family — a gap to add on our side.

## Why the totals are not comparable

UIBC Core's corpus is 21 families built by its own author (including rollback and whole-bundle replay). The proofbundle corpus here is the 10 families applicable to a **single-leaf bundle** (rollback/reorder are structurally `N/A`). Therefore:

- compare **rates within a tier**, never 90.5% vs 70.0% as a ranking;
- report `not_applicable` explicitly (both scorecards do);
- widen the proofbundle corpus (multi-leaf bundles, checkpoint fixtures) before drawing any stronger conclusion.

## Reproduction commands

```bash
python tools/erm_scorecard.py mutation_benchmark.json out_uibc.json
python adapters/proofbundle_adapter.py --exe /path/to/proofbundle --out out_pb.json
```

Both scripts write `erm-scorecard/v0.1` JSON. Deltas welcome as issues; the scorecards are not edited after the fact.

## Conflict disclosure

UIBC Core is maintained in the same ecosystem as this repo's author. proofbundle is an independent third-party project. Both runs used the same tool-agnostic mutator where the bundle format allowed it. Numbers are reproducible; disagreement should be recorded as a delta, not silently corrected.
